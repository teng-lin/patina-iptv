# Patina IPTV repository audit — 2026-11-16 (Claude)

Audited commit: `b289c587` (master). Nine reviewers each took one angle and worked
independently; a lead then re-checked the most severe findings against the code and
GitHub and merged the reports. Nobody on the team opened `2026-11-16-codex.md`, so this
audit is independent of it.

## Verdict

**Overall: 7 / 10.** The engineering underneath is strong for any project and
remarkable for one that is eight days old: enforced layering, a careful FFI boundary,
bounded parsers, a behaviour-focused test suite that is green at HEAD, and a hardened
supply chain. No blocker was found. The score is held down by what sits on top of that
base:

- **The product surface is ahead of its completion.** More than half of the visible
  settings rows do nothing, number-key channel entry is missing, and programme details
  show fixture text.
- **The release practice is behind the release design.** The current "Latest" release
  was published by hand around the pipeline and lacks the provenance the docs promise.
- **Sustainability is the largest structural risk.** One maintainer, 997 commits in
  eight days, a permanent UI-framework fork, and CI tooling a fifth the size of the
  production code.

## Method and limits

- **Team.** Architecture; non-UI code quality; app/player/host code quality; testing;
  CI/CD; deployment; UX/UI; security; documentation and maintainability.
- **Read-only.** Nothing tracked was modified. Only the testing reviewer ran `cargo`.
  The CI, release and security reviewers used read-only `gh` queries.
- **Sampling.** The workspace is about 149k lines of Rust under `src/` plus 52k of
  tests. No reviewer read everything; each report listed what it sampled, summarised
  under [Not checked](#not-checked).
- **Evidence labels.**
  - *verified*: the lead re-checked the cited code or GitHub state after the reviewer
    reported it.
  - *confirmed*: the reviewer traced the code path; the lead did not repeat it.
  - *inferred*: reasoned from code, not traced end to end or not run.
- **Severity.** P0 blocker, P1 high, P2 medium, P3 low. Severities are per area; a P1
  in UX is a product gap, not a crash.
- **Already tracked.** Where a finding matches an ID in `docs/plans/` or
  `docs/reviews/rust/`, the ID is given. Reviewers consulted those only after their own
  analysis.
- **No live app run.** UX/UI was assessed from code, docs and committed screenshots.
  No device, emulator, macOS, Windows or iOS run was made by this audit.

## Architecture — 7 / 10

Sub-ratings: layering 8.5, concurrency and lifecycle 7.5, state model 6,
extensibility 6, docs versus code 7.

### Strengths

- **The dependency graph matches the documented design.** `cargo metadata` shows no
  upward edges. The nine portable crates carry no NSH, tokio or platform dependencies,
  and all nine build for wasm32 (run in this audit).
- **Boundaries are ratcheted by tests.** `crates/iptv-runtime/tests/it/architecture.rs`
  and `shell_boundary.rs` pin dependencies, statics and what the shell may name;
  `crates/iptv-app/tests/app/architecture.rs` lists every shell static with a purpose.
- **Sans-IO ports are real.** `Fetch` and the sinks live in `iptv-import`; `iptv-net`
  and `iptv-store-sqlite` implement them.
- **The runtime concurrency model is coherent.** Per-owner FIFO store lanes on
  dedicated threads with epoch-stamped handles
  (`crates/iptv-runtime/src/store_service.rs:56-91,256-285`), a bounded refresh pool
  with `catch_unwind` (`workers.rs:7-8,51`), and an assertion that the UI thread stays
  off the store (`store_service.rs:189-194`).
- **Focus identity is honoured.** `lists::Kept { list, key }` restores through
  `find_channel(&key)` (`crates/iptv-app/src/lists.rs:119-185`).
- **Surface 0 is persistent.** `video::layer(ui, 0)` is an unconditional child
  (`crates/iptv-app/src/lib.rs:862`), and a zero-size rect stands in for hiding
  (`video.rs:102-107`).
- **Runtime API v1 is backed by code.** All 18 documented methods exist, with a
  compile-only consumer in `tests/it/foundation_contract.rs`.

### Findings

- **A1 · P2 · Catalog index is the state currency** (verified).
  `PictureSettings.per_channel` is a `BTreeMap<usize, PictureSize>`
  (`crates/iptv-core/src/player_options.rs:62`), written with
  `ui.playing…unwrap_or(0)` (`crates/iptv-app/src/chooser.rs:237`) and never remapped
  when the schedule changes. After a refresh that reorders channels the size lands on a
  different channel; during VOD playback it is filed under channel 0. `ui.playing`,
  `favorites: BTreeSet<usize>` and `RuntimeEvent::ResumeChannel(usize)` use the same
  currency and are re-synced by key one tick later (`player.rs:1001-1005`); the
  one-tick stale window is inferred. `iptv-search-001` tracks another instance.
  Fix: key `PictureSettings` by content key now; introduce a `ChannelRef` newtype
  resolved at the schedule boundary.
- **A2 · P2 · `Runtime` and `Ui` are god-objects** (confirmed). `Runtime` has 55
  `Cell`/`RefCell` fields including about ten hand-rolled generation counters
  (`crates/iptv-runtime/src/lib.rs:102-160`); `owner.<field>.borrow…` appears about 170
  times across 12 modules. `Ui` is 59 public signals (`crates/iptv-app/src/lib.rs:186-289`)
  with 378 direct set/update sites. Several tracked P1s (`runtime-003`, `guide-002`,
  `app-002`, `app-003`) are stale-reply defects of exactly this shape.
  Fix: split `Runtime` into sub-owners with `pub(super)` fields and one shared
  generation/ticket type.
- **A3 · P2 · Auxiliary player windows fork `Ui` field by field** (confirmed).
  `desktop/player_windows.rs:310-366` copies about 45 fields by hand, so a field added
  later silently aliases the main window's signal. This is also a third source of
  `tv.player` instances that `AGENTS.md` does not name.
  Fix: split `Ui` into shared `AppState` and per-window `Presentation`.
- **A4 · P2 · `iptv-core` is both the dependency root and the UI state machine**
  (confirmed). `iptv-providers` and `iptv-epg` depend on the 19k-line core only for the
  101-line `import_limits.rs`. Core had 88 commits in three days, 37 of them touching
  `i18n/messages.tsv`, and each invalidates all 14 other crates.
  Fix: extract a small `iptv-domain` or `iptv-limits` crate.
- **A5 · P3 · The shell keeps the ambient owner the runtime forbids** (confirmed).
  A thread-local `RUNTIME` (`crates/iptv-app/src/lib.rs:467-502`) is reached by 248
  `runtime()` calls; in release builds an off-thread call silently creates a
  never-started owner (`lib.rs:489-498`).
- **A6 · P3 · "State lives in the core" is only partly true** (confirmed). `ViewMode`,
  the overlay stack, the 85-line `go_back` chain (`lib.rs:1068-1153`) and the 233-line
  `input::apply` live in the shell. `Overlay::ALL` claims to mirror z-order but lists
  Recordings and Vod above the guide-repair overlays while `ui_layers` mounts them
  below (`overlays.rs:74-95`, `lib.rs:961-972`).
- **A7 · P3 · Leaky `Schedule` and provider spread** (confirmed). `dyn Schedule` has
  32 methods plus `as_any`, downcast at 19 sites. `SourceConfig`/`SourceKind` are
  matched at about 130 sites in 29 files, so a fourth provider is a six-crate edit.
- **A8 · P3 · Docs lag the code** (confirmed). `docs/architecture.md:309` says two
  store connections; there are three lanes (`store_service.rs:99-104`). `AGENTS.md`
  says never re-parent the player view, but macOS PiP deliberately moves the native
  `NSView` between windows (`crates/iptv-player-mpv/src/mpv/mac_pip.rs:54,60,209`); the
  rule needs scoping.

## Code quality: non-UI crates — 7 / 10

### Strengths

- **Unsafe is nearly absent.** Ten of twelve crates declare `#![forbid(unsafe_code)]`;
  production has three `unsafe` blocks, each with a SAFETY comment that holds up.
- **Panics are rare.** About 45 `unwrap`/`expect`/`panic!` sites in roughly 63k
  non-test lines, nearly all behind a checked precondition. No TODO/FIXME markers.
- **Untrusted input is bounded.** `ImportLimits`
  (`crates/iptv-core/src/import_limits.rs:33-50`) is enforced in the XMLTV, M3U and JSON
  parsers.
- **Migrations are disciplined.** One `BEGIN IMMEDIATE` transaction with a re-check
  and per-version schema snapshots (`crates/iptv-store-sqlite/src/migrate.rs:165-200`).
  SQL uses bound parameters throughout.
- **Errors do not leak secrets.** Redacted `Debug` (`crates/iptv-net/src/client.rs:79-93`)
  and URL-stripped transport errors.

### Findings

- **C1 · P2 · Recording status transitions discard the write result** (verified;
  trigger frequency inferred). `transition` does `let _ = services.call(…)`
  (`crates/iptv-runtime/src/recordings.rs:963-968`), dropping both `Err` and the
  compare-and-set `Ok(false)`. If the final write fails (disk full, or `SQLITE_BUSY`
  from the second in-process writer in background-recording mode), the job stays
  `Recording` with its file already renamed, and the next supervisor pass relabels a
  complete recording as `Partial`.
  Fix: return the result, retry the terminal transition with bounded backoff, and let
  recovery distinguish a finalized file from a `.part`.
- **C2 · P2 · Blocking file I/O on the two-worker async runtime** (verified; impact
  inferred). `Writer::write` is an `async fn` calling `std::fs::File::write_all`
  (`crates/iptv-net/src/recording.rs:241-249`); HLS segments up to 32 MiB go out in one
  call. Captures run on the runtime built with `worker_threads(2)`, up to four at once,
  alongside the live relay tasks.
  Fix: a dedicated writer thread per capture behind a bounded channel.
- **C3 · P2 (latent) · `CancelToken` evicts waiters beyond 32** (verified; tracked as
  `iptv-import-001`). `crates/iptv-import/src/cancel.rs:72-77` does `wakers.remove(0)`
  and nothing deregisters on drop. Today's callers are saved by a deadline or a
  one-second re-poll, so the effect is delayed cancellation, not a hang.
- **C4 · P3 · One ancient programme without a stop drops a channel's schedule**
  (verified). `crates/iptv-epg/src/settle.rs:89` takes `base` from the first row before
  any drop decision; a year-0001 start with no stop makes every later row fail
  `u32::try_from(start - base)` (`:111`).
  Fix: anchor `base` on the first surviving row.
- **C5 · P3 · Recording quota contradicts "four simultaneous recorders"** (verified).
  `recordings.rs:1332-1343` fails when `active × 8 GiB + directory bytes > 32 GiB`, so
  the fourth recorder fails once any file has a byte. Free space is never checked.
- **C6 · P3 · The recorder supervisor polls at 1 Hz forever** (confirmed), with three
  queries per source each pass (`recordings.rs:1056-1198`), contradicting "nothing
  polls" at `executor.rs:14-15`.
- **C7 · P3 · Shutdown waits add up** (confirmed). Up to 15 s in `stop` plus 10 s per
  store lane: about 45 s worst case against a stated 10 s limit
  (`crates/iptv-runtime/src/lib.rs:293-317`).
- **C8 · P3 · The runtime's error type wraps `StoreError`** (confirmed). Network and
  capacity failures become `StoreError::Unavailable(&'static str)` carrying user-facing
  English; causes are discarded 165 times with `map_err(|_| …)`.
- **C9 · P3 · Smaller items** (confirmed).
  - The favourites writer retries a failing write every 250 ms forever
    (`favorites.rs:572-590`).
  - The EPG interner uses an unkeyed hash with linear chains
    (`crates/iptv-epg/src/intern.rs:87-96`); a hostile feed could force quadratic import
    time (exploit inferred).
  - `iptv-sqlcipher-init` binds a private SQLCipher symbol by hand while the manifest
    allows any `rusqlite` 0.42.x.
  - The workspace enables two lints and has no clippy configuration; `unwrap_used` and
    cast lints would mechanise conventions the code already follows.
  - Long functions: `prepare` at about 570 lines
    (`guide_repair/prepare.rs:90`), `pipeline` at about 370 (`imports.rs:402`).

## Code quality: app, player, Android host — 7.5 / 10

### Strengths

- **Unsafe discipline.** The workspace denies `undocumented_unsafe_blocks` and
  `unsafe_op_in_unsafe_fn`; `iptv-player-mpv` carries 111 SAFETY comments.
- **Render/control split.** All blocking mpv calls run on a control thread; callbacks
  wake the main loop by id through a `Weak` registry
  (`crates/iptv-player-mpv/src/mpv/mod.rs:149-177`).
- **Fail-closed mpv sandbox.** `Mpv::new` refuses to initialise if `config`,
  `load-scripts`, `ytdl` or `autoload-files` cannot be disabled (`handle.rs:17-31`).
- **Panic containment at every foreign boundary.** JNI entry points and the Win32
  timer callback use `catch_unwind`.
- **Android manifest and Gradle hygiene.** Backup off, cleartext limited to
  `127.0.0.1`, only the launcher exported, immutable PendingIntents, env-driven release
  signing that fails without an explicit choice, and a Keystore-wrapped database key.
- **`iptv-nav` is clean.** Pure, saturating arithmetic, with tests for missed releases
  and IR remotes without repeat.

One reviewer listed "unwired settings are kept off screen" as a strength. The lead's
check contradicts it: unwired keys default to `Offer::NotYet`
(`crates/iptv-app/src/settings.rs:194-196`) and render as dimmed rows. See U1.

### Findings

- **P1 · P2 · Refused loads never complete** (verified; tracked as
  `iptv-player-mpv-001`). `Cmd::Load` returns only `Note::TransportError` on its
  refusal paths (`crates/iptv-player-mpv/src/mpv/worker.rs:328-331`), but the main side
  has already incremented `st.loads` and emitted `Buffering` (`mod.rs:595-596`), and
  `TransportError` only stores a clue (`mod.rs:865`). No error is sent, `loads` never
  decrements, and every later `Loading` note is discarded: the handle never reports
  Ready again. Triggered by any libmpv without the relay-guard FFmpeg patch, which is
  what Linux links when the pinned runtime is not on the path.
  Fix: answer every `Load` with exactly one `Loading(None)` plus the error code.
- **P2 · P2 · Command replies wait behind an infinite `mpv_wait_event`** (verified;
  tracked as `iptv-player-mpv-002`). Notes from `execute` set `sent`, but the loop
  blocks with `timeout = -1.0` before `notify()` (`worker.rs:232-245,306-308`). On a
  quiet handle a reply sits in the channel until the next mpv event.
  Fix: notify before waiting, or wait with timeout 0 when `sent` is true.
- **P3 · P2 · Programme details show fixture text** (verified; tracked as
  `iptv-app-004`). `crates/iptv-app/src/menu_view.rs:486` renders "A synthetic
  programme description for testing the guide. Real descriptions come from the EPG."
  for every programme, untranslated. The header already reads real descriptions.
- **P4 · P2 · Returning from background is signalled as a fake player error**
  (confirmed; not tracked). Android `foreground()` emits `ERROR_CODE_IO_UNSPECIFIED` or
  a fake HTTP 429 (`PlayerComponent.kt:576-591`), and iOS does the same. For non-live
  content that has not reached Ready, `retry` is false (`health.rs:266-279`), so
  switching apps while a movie buffers produces a failure card. Live streams burn a
  retry attempt on every resume.
  Fix: a dedicated `reauthorize` event that reopens without touching failure accounting.
- **P5 · P3 · Player create and destroy run synchronously on the UI thread** (code
  path confirmed, stall inferred; tracked as `iptv-player-mpv-003`).
- **P6 · P3 · Windows video is software-rendered on the UI thread** (confirmed;
  impact inferred). `mpv_render_context_render` with the `sw` API runs inside the D2D
  draw, and a new `ID2D1Bitmap` is created on every paint (`win.rs:220-267`).
- **P7 · P3 · View state outside `Ui` and core** (confirmed). Thread-local stashes in
  `seek.rs:51-56`, `settings_view.rs:105-109`, `lists.rs:30` and `desktop.rs:31-33`
  outlive an Android root recreation; `video.rs:136-165` counts opens for tests in
  production builds.
- **P8 · P3 · Android polish** (confirmed). Recording notification strings are
  hard-coded English (`RecordingHost.kt:180,194-195`); the ktlint baseline suppresses
  401 violations across all 16 Kotlin files; `isMinifyEnabled = false`; dead
  `SDK_INT >= 26` branches with `minSdk 26`.

## Testing — 8 / 10

### Strengths

- **Healthy pyramid.** 1,199 in-crate unit tests, 674 integration tests (179 of them
  whole-app headless scenarios), 25 Android JVM tests, emulator smoke, 9 fuzz targets,
  8 property tests and 356 Python CI-tool tests.
- **Tests assert behaviour.** Names are behaviour sentences and there is no mocking
  library; fakes are real SQLite files, loopback HTTP servers and a virtual-clock
  `Fetch`.
- **Migrations are covered for all 19 schema versions**, with both schema and data
  fixtures (`crates/iptv-store-sqlite/tests/it/migrations.rs:560`).
- **Isolation.** Each app scenario runs in a child process with a fresh `HOME`, TZ and
  locale. No flakes across two full runs.
- **The player FFI is tested.** 60 tests drive real libmpv through surfaceless EGL,
  and CI turns skips into failures.
- **Coverage floors are real ratchets.** Per-crate floors of 88–97% with actual minus
  floor between +0.8 and +8.3 points at HEAD.
- **The test-target budget is met and enforced** by `tools/ci/test-check-plan.py`.

### Findings

- **T1 · P2 · Local "check before finishing" evidence is not hermetic** (symptom
  verified; mechanism inferred). The worktree at
  `/home/blackmyth/src/patina-rust-review/patina-iptv` (branch
  `fix/rust-workspace-review`, uncommitted edits) builds into this repo's `target/`.
  Its `iptv-settings` has `pub(crate)` key fields where HEAD has `pub`
  (`crates/iptv-settings/src/keys.rs:7`), and Cargo treats the stale artifact as fresh.
  All three `AGENTS.md` finishing checks can be false-green or false-red while parallel
  sessions work. The default `target/` is still in that state; this audit did not
  clean it, to avoid disrupting the other session.
  Fix: have `tools/check.sh` refuse a target directory not owned by the worktree, and
  document one target per worktree.
- **T2 · P2 · Tests never execute the production configuration** (confirmed). Every
  Rust test step enables both `test-support` features, which gate 132 `cfg` sites. The
  only test of the real database-key path is both `cfg(not(feature = "test-support"))`
  and `#[ignore]` (`crates/iptv-app/src/credential_key.rs:153,178`), and no workflow
  enables it. A broken key path means an unreadable encrypted store.
  Fix: a nightly lane that runs it inside `dbus-run-session` with a throwaway keyring.
- **T3 · P2 · Crash recovery is verified only from hand-built states** (inferred).
  Tests rename or corrupt files and then call recovery; nothing kills a process mid
  operation. Restore swap, catalogue publication and recording finalisation are
  multi-step filesystem sequences.
  Fix: reuse the child-process pattern to kill at each step boundary.
- **T4 · P2 · The Android host adapter relies on emulator smoke** (inventory confirmed;
  risk inferred). `PlayerComponent.kt` (676 lines), `PipHost.kt`, `RecordingHost.kt`
  and `BackupComponent.kt` have no tests and there is no `androidTest/`. Smoke is
  log-pattern matching on x86_64 emulators.
- **T5 · P3 · Coverage is line-only, Linux-only and no longer a PR gate** (confirmed).
  `tools/ci/validation-plan.py:52,125` selects it only for nightly, release and
  coverage-tooling changes. See I4.
- **T6 · P3 · Fuzz oracles and corpus are thin** (confirmed). Eight of nine targets
  only detect panics; six have one seed; the corpus lives only in the Actions cache.
  There is no Miri or ASan lane for about 200 `unsafe` sites in `iptv-player-mpv`.
- **T7 · P3 · Scenario megatests with real-time waits** (confirmed).
  `cov_data_player.rs:352` is one 738-line test; there are 35 fixed `app.wait(…)`
  calls, including one of 6.5 s.
- **T8 · P3 · A stock libmpv gives eight minutes of misleading red** (confirmed). Ten
  tests each wait 60 s. A fail-fast preflight would name the fix; see also P1.
- **T9 · P3 · Tests leak recording directories outside their tempdir** (confirmed).
  Each suite run leaves 15 `.tmp*-recordings` directories in `/tmp`.

## CI/CD — 7 / 10

### Strengths

- **A single fail-closed aggregate.** `validation` needs every lane with
  `if: always()` (`.github/workflows/validation.yml:148-160`), and `gate()` rejects

## Security and privacy — 8 / 10

No P0 or P1. Advisory status is from an offline `cargo deny` run against a 13 Nov
database snapshot.

### Strengths

- **TLS.** rustls with compiled-in Mozilla roots and no accept-invalid-certs switch
  anywhere; environment proxies are ignored.
- **SSRF and DNS rebinding.** Content-supplied URLs must be public, and every DNS
  answer is checked and pinned (`crates/iptv-net/src/public_resolver.rs:22-28`).
- **Loopback relay.** Binds `127.0.0.1:0` with a 192-bit capability compared in
  constant time, and forwards only Range headers from the player.
- **mpv.** Only `http(s)` is playable, every load goes through the relay behind a
  guard that fails closed, and playlist headers never become mpv options.
- **At rest.** SQLCipher with a random 256-bit key held by the OS broker; on Android
  it is wrapped by a non-exportable Keystore key and fails closed.
- **Secrets in logs.** `Secret`/`SecretUrl` zeroize and redact; a survey of about 230
  `log::` sites found no URL or credential logged.
- **Hygiene.** A history scan found no keystores, key material, real provider hosts or
  credentials. There is no telemetry, analytics or crash-reporting SDK.

### Findings

- **S1 · P2 · Portable backups are plaintext with no passphrase option** (verified as
  a documented design choice). `docs/security.md:46-57` says "Backup passphrases remain
  a separate feature". One `.patinabackup` file yields all logins, portal MACs and
  tokenised URLs, bypassing SQLCipher and the Keystore; on Android it can be written to
  any storage provider. The UI does warn.
  Fix: an optional passphrase (Argon2id plus AEAD over the existing container).
- **S2 · P3 · Logo decoding on Linux has no pixel-dimension bound** (inferred). Logos
  are capped at 4 MiB but handed to NSH's `image::load_from_memory` with no dimension
  limit; a small, highly compressed image could force very large allocations.
  Fix: reject by dimensions before building the data URI.
- **S3 · P3 · Xtream streams are exempt from the public-address rule** (verified for
  the code path; impact reasoned). `crates/iptv-guide/src/playback.rs:320` sets
  `public_only = false` for every Xtream stream, while Stalker allows private
  addresses only on a private portal's own host. A hostile provider controlling its DNS
  could make the device send blind GETs into the LAN.
  Fix: mirror the Stalker rule.
- **S4 · P3 · The "Not encrypted" warning covers only the typed source address**
  (confirmed). An HTTPS-delivered playlist can list `http://` streams whose paths embed
  credentials, with no indication to the user.
- **S5 · P3 · `docs/security.md` misdescribes the Android cleartext policy**
  (verified). `:83-85` says the config "permits explicit HTTP"; the shipped
  `network_security_config.xml` denies cleartext except `127.0.0.1`. The shipped config
  is the safer one.
- **S6 · P3 · The compile-time `IPTV_RS_DEV_PLAYLIST` hook is live in release builds**
  (verified for the code; exposure hypothetical). `option_env!` at
  `crates/iptv-runtime/src/imports.rs:1034` is not gated on `debug_assertions`; a
  release built with the variable set would embed that URL.
- **S7 · P3 · No privacy statement** (confirmed). Nothing states what leaves the
  device or documents the default User-Agents.
- **S8 · P3 · Dependency and fuzz posture gaps** (confirmed). `deny.toml:6` ignores
  one advisory with no expiry; vendored OpenSSL inside SQLCipher needs CVE tracking;
  fuzzing does not reach the MPEG-TS ingest, the relay request parser or the Stalker
  parsers.

## Recommended sequence

1. **Restore release integrity.** Ship v0.1.5 through the pipeline after one
   rehearsal, add the changelog gate, and correct the provenance claims (R1, R2, R8).
2. **Fix the confirmed defects that users can hit.** The mpv worker loop (P1, P2),
   fixture text in programme details (P3), the resume-as-error path (P4), the recording
   transition (C1) and index-keyed picture size (A1).
3. **Close the product gaps or hide them.** Hide inert settings and disabled menu
   items in release builds; implement digit entry (U1, U2, U3).
4. **Close the CI holes.** Add the iOS compile check, require the aggregate context,
   treat test-read docs as code inputs, and alert on nightly failure (I1–I4).
5. **Make local validation trustworthy.** One target directory per worktree, and a
   lane that runs the production configuration (T1, T2).
6. **Bring the docs back in line.** `docs/release.md`, `docs/security.md`, and the
   NSH fork's real status (D1, D2, S5, M1).
7. **Then the structural work.** Split `Runtime` and `Ui`, extract a small domain
   crate from `iptv-core`, move blocking recording I/O off the async workers, and add
   an optional backup passphrase (A2–A4, C2, S1).
