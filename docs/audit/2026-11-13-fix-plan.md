# Fix plan for the 2026-11-13 audit

This plan covers the findings in [`2026-11-13-consolidated.md`](2026-11-13-consolidated.md) (IDs `C01` to `C41`). It groups them into as few pull requests as is safe to review and verify.

## Shape of the plan

Six pull requests fix everything at P1 and P2 and most of P3. A later series of three does the structural refactor, which cannot sensibly be one change.

| PR | Title | Priority | Findings | Size | Depends on |
|---|---|---|---|---|---|
| **A** | Transport privacy and guide resilience | P1 | C01, C05, C39, C36, C38 (network items), C28 (rewriter fuzzing) | M | none |
| **B** | Repository, CI and release gates | P1 | C02, C04, C06 (interim), C20, C24, C27 (Windows), C28, C29, C30 | M | none |
| **C** | App correctness and hardening | P2 | C07, C23, C21, C32, C10, C03, C11, C22, C38 (app items), C31 (labels) | M | none |
| **D** | Storage and threading responsiveness | P2 | C12, C13, C14, C15, C08, C40 | L | C |
| **E** | Android host hardening | P2 | C34, C35, C27 (Android) | S | B |
| **F** | Pinned media runtime and desktop signing | P2 | C26, C06 (final), C25 | L | B |
| **R1 to R3** | Structural refactor series, see [`2026-11-13-refactor-plan.md`](2026-11-13-refactor-plan.md) | P3 | C16, C17, C18 | L | A, C, D |

A and B can be written in parallel and should both land before the next release (v0.1.2). C, E and F are independent of each other. D follows C because both edit `iptv-app/src/data.rs`. F follows B because both edit `release.yml`.

### Why these groupings

- **One area of the code per PR.** A touches only `iptv-net`, `iptv-import`, `iptv-providers` and `fuzz/`. B touches no product code. C and D are both in `iptv-app` but differ in risk: C is small local fixes, D changes threading and needs measurement. E is the only one that touches Kotlin and Gradle, so the device run AGENTS.md requires happens once. F is packaging only.
- **P1 is not held up by slow work.** The licensing fix (C06) is split: an interim source offer ships in B, and the lasting fix (building the libraries from pinned sources) is F.
- **Nothing structural is mixed with a bug fix.** The refactor series moves code, so it would hide behaviour changes in review.

## Later: structural refactor series (P3)

Planned separately in [`2026-11-13-refactor-plan.md`](2026-11-13-refactor-plan.md). In short: R1 moves the player and the library model into their own crates without changing behaviour (after PR A and PR C); R2 puts an application runtime between the views and the store (after PR D); R3 optionally moves that runtime into its own crate. The provider plug-in point (C41) is dropped.

## Not covered by a pull request

- **C19 (one author, bot-only review).** A process change: get a human reviewer on core and app changes.
- **C33 (Stalker credentials follow the host on any port).** Left as designed. Tightening it to the full origin would break portals that serve streams on a second port.
- **C37 (plaintext portable backups).** A feature, not a fix; schedule it with product work.
- **C31 (plural and date formatting, CJK font, screen-reader testing).** Product work beyond the label fix in PR C.
- **NSH upstreaming (C20).** Happens in the NSH repository.
