This plan covers the findings in [`2026-11-14-consolidated.md`](2026-11-14-consolidated.md) (IDs `D01` to `D25`) and the first-round residues it carries over. It groups them into as few pull requests as can each be reviewed and verified on their own.

### Why these groupings

- **One area of the code per PR.**
  - G touches only `iptv-net`, `iptv-player-mpv` and `fuzz/`. #37 touches none of those, so G does not wait for it.
  - H touches no product code: workflows, release scripts, test harness, docs.
  - I and R4 are both in the runtime and the shell, and are split by risk. I changes behaviour and needs measurement; R4 moves code and must not change behaviour.
  - J touches text and view code.
- **Everything in the runtime waits for #37.** It moves `crates/iptv-app/src/runtime/` to a new crate. A fix written against the old paths would have to be redone.
- **Fixes land before the move.** D04 and D05 are user-visible and small. R4 then moves the fixed code, as PR D preceded R2 yesterday.
- **One device session per PR that needs one.** Only I and R4 change Android behaviour. J needs a device for the screen-reader checklist.

### The cost of fewer PRs

D17 in the audit asks for PRs under about 1.5k lines, and this plan asks for few PRs. Those pull against each other. Five is the smallest number that keeps a bug fix out of a code move and keeps P1 work from waiting on slow work. I, J and R4 will each exceed 1.5k lines. To keep them reviewable:
- each lands as a series of commits that pass `tools/check.sh` one by one, so it can be reviewed commit by commit;
- R4 and J each have a marked split point, to use if the diff passes about 3k changed lines;
- no PR merges with its bot review skipped (see decision 3).

## PR G: Transport hardening (P1)

| Finding | Change | Test |
|---|---|---|
| D01 | Parse each HLS tag's attribute list instead of searching for `URI="`. Rewrite a `URI` value whether quoted or not and emit it quoted. Refuse a tag line whose `URI` cannot be parsed. | Unit tests for quoted, unquoted, repeated and malformed `URI`. Extend the fuzz oracle in `fuzz/fuzz_targets/manifests.rs` so that no `URI` value of either form may point outside the relay. |
| D01 | Give mpv a second guard for loads the demuxer makes itself, as `RelayGuard` is for Media3. First choice: make the relay mpv's HTTP proxy and have it refuse any request outside the stream's capability. See decision 1 for the fallback. | A test with a real mpv and a manifest the rewriter is told to pass through: the nested load must fail, and no request may reach the second server. |
| D02 | Before `Origin` crosses origins, reduce it to a serialized origin with the helper `Referer` already uses. Drop it when it is `null`, has userinfo, is not HTTP(S), or does not parse. | Two-origin redirect and sub-resource tests with a path-and-query `Origin`, `null`, and a malformed value. Same-origin requests keep the value. |
| D25 | Refuse a DASH manifest whose XML declaration names anything but UTF-8 or US-ASCII, or whose body is not valid UTF-8, or which contains C0 controls other than tab, CR and LF. | Unit tests with an ISO-2022-JP declaration and with an escape byte. |
| D22 (relay) | Shorten the relay's wait for the first request line to about one second, close connections whose first bytes are not the capability path, and compare the token in constant time. | A test that idle sockets do not exhaust the 12 slots. |

**Check before merge:** `tools/check.sh`; the real-mpv suite with `IPTV_REQUIRE_PLAYER_TESTS=1`; 60 s of each fuzz target; the D01 reproduction (an unquoted key URI on loopback) no longer reaches the second port, run against the pinned Linux runtime, not only the system mpv. ## Not covered by a pull request

- **D15 (unsigned desktop builds).** Needs an Apple Developer ID and a Windows signing identity. The workflow is ready and builds stay labelled previews until then. Verify signatures on a real release candidate before dropping the label.
- **D17 (one author, bot-only review).** A process change; see decision 3.
- **D22, DNS re-pointing.** Trusting a user-entered host by name is a design trade-off. Fixing it means recording whether a source was public when added, which needs a schema change and a rule for existing sources. Schedule it as its own change if it matters to you.
- **D22, restored backups trusted as user input; C37, plaintext backups.** Both are features: a host review step before a restore activates, and passphrase-protected exports.
- **D22, private certificate authorities.** The relay honours extra roots but no setting supplies them. A product decision.
- **C02 (old screenshot in history), C33 (Stalker credentials follow the host), C36 (proxy).** Unchanged from the first plan: left as decided or as designed.
- **iOS tests, three `getrandom` versions, NSH upstreaming.** Outside this cycle.
