# Patina IPTV: repository audit (2026-11-13)

- **Auditor:** Claude Opus 5.5 (Claude Code), with a team of seven parallel reviewer agents
- **Revision:** `8c259ee` on `master` (v0.1.1)
- **Scope:** the 11 workspace crates (~118k tracked lines of Rust), the Android host (Kotlin), CI workflows, packaging tools, docs and git history
- **Method:**
  - Each reviewer worked read-only on a single aspect, citing `file:line` evidence.
  - Only the testing reviewer ran builds: tests, clippy, fmt, deny, the wasm builds and the app scenarios.
  - Key claims were then checked by hand. The real-data screenshot, debug-key signing fallback, `group_of` complexity and flaky scenario were confirmed by reading the files.
  - The other reports in `docs/audit/` were not consulted.

## What's genuinely good

1. **The portability rule is enforced by the build.** `iptv-core` has zero dependencies and `#![forbid(unsafe_code)]`. All eight portable crates are built for `wasm32-unknown-unknown` in `tools/check.sh:12-14`, which CI runs. A grep for `std::fs`, `std::thread`, `tokio` and `cfg(target_os)` in the core crates finds nothing that breaks the rule.
2. **Sans-IO is real, not just a label.** Providers build `HttpRequest`/`HttpResponse` values (`iptv-providers/src/http.rs`). Import drives them through the `Fetch`, `BodyStream` and `*Sink` ports (`iptv-import/src/fetch.rs:23-70`). `iptv-net` is the only reqwest adapter, and the clock is passed in.
3. **Security choices**
   - **Database key:** a random 256-bit SQLCipher key held in the platform keystore. On Android it is wrapped with AES-GCM in the Keystore. If the keystore is unavailable, the app refuses to open rather than falling back to plaintext (`credential_key.rs:72-138`).
   - **Secrets in logs:** the `Secret`/`SecretUrl` types render as `***`, and `redacted_url` also catches percent-encoded secrets.
   - **TLS and redirects:** rustls with webpki roots and no custom verifier; manual redirects refuse HTTPS→HTTP and drop identity headers when the origin changes.
   - **SSRF:** checked inside the DNS resolver, so rebinding is covered.
   - **Player relay:** listens on loopback only, behind a 192-bit token.
   - **mpv:** started with `config=no`, `load-scripts=no` and `ytdl=no`, and these are verified.
   - **Backup restore:** checks the schema against a reference schema, and runs `integrity_check` and `foreign_key_check`.
4. **Data integrity**
   - Catalog and guide imports stream into a private staging DB and are published in one `BEGIN IMMEDIATE` transaction (`catalog_stage.rs:323-368`), so a crash mid-import leaves the old data intact.
   - Migrations only move forward, run atomically, refuse a newer database version, and are tested from every historical schema (v1–v8) with seed data.
   - Restore and settings writes use fsync and rename.
5. **Tests check behaviour, and the gates are strict.**
   - About 1,130 Rust tests.
   - Property tests check that chunked parsing equals buffered parsing.
   - Memory tests assert heap bounds while importing 100k channels.
   - Headless UI scenarios run in isolated processes.
   - CI on Linux and macOS runs `fmt`, `clippy -D warnings` (0 warnings measured), `cargo deny`, the wasm builds and the app scenarios with `IPTV_REQUIRE_PLAYER_TESTS=1`.
6. **Release engineering is well above what a v0.1 usually has.**
   - v0.1.1 shipped APK, AAB, deb, rpm, pacman, AppImage, DMG and setup.exe, plus `SHA256SUMS`.
   - Signing runs on a fresh runner behind a reviewer-gated environment.
   - Every action is SHA-pinned.
   - Every downloaded binary (MPVKit, libmpv, linuxdeploy, Gradle, Inno Setup) is hash-verified.
   - Every package is installed and launched in CI.
   - The Windows libmpv is built from pinned sources with no network access, and its sources ship with the release.
7. **Unsafe hygiene.** 10 of 11 crates forbid unsafe code. All unsafe code is in the app's mpv and platform FFI layer, and every block carries a `SAFETY` comment. The workspace denies `undocumented_unsafe_blocks`.
8. **Asset provenance.** The fonts are pinned by SHA-256 with a subsetting script, and the icon's provenance is documented. The palette in `theme.rs` is original, as AGENTS.md requires.

### Low-severity security notes

- **Debug-key fallback for release builds.** The release build falls back to the debug signing key when no distribution keystore is configured (`hosts/android/app/build.gradle.kts:45-46`). The comment says this is intentional for local installs. CI release signing is separate and verified, but a misconfigured build would ship a debug-signed APK silently.
- **`profileable` in release.** `<profileable android:shell="true"/>` is in the release manifest (`AndroidManifest.xml:26`), which lets anyone with adb access profile an app that holds credentials.
- **Plaintext viewing data.** `search-history.json` and `last_channel*` sit outside the encrypted DB, as non-atomic plaintext writes.
- **Windows reserved names in restore.** `backup_manifest::allowed` doesn't reject Windows reserved names (`CON`, `NUL`, `COM1`, …) or names ending in a dot or space (`iptv-import/src/backup_manifest.rs:29`).
- **No zeroize on drop.** `Secret` doesn't zeroize its contents when dropped (`iptv-providers/src/secret.rs:11`).
- **Private CAs at playback.** The playback relay ignores `extra_roots_der` (`iptv-net/src/playback.rs:225`). It fails closed, but a private-CA server can import and then fail to play.

## Recommendations (prioritised)

1. **Replace `docs/screenshots/tablet-guide.png`** with a capture using the synthetic fixtures, and drop the README caveat. Decide whether to rewrite history.
2. **Meet the FFmpeg source obligations for the DMG and AppImage.** Either build them from the existing pinned `tools/mpv-runtime` pipeline, preferably as an LGPL-only build, or attach the exact sources to the release. This also fixes the problem that these bundles silently pick up whatever versions are current.
3. **Make guide import resilient.** Use an idle (no-bytes) timeout plus a large total cap, give each source its own budget, and add bounded exponential backoff for network and 5xx errors.
4. **Index channel → group once per schedule.** Make `group_channels` return a borrowed slice, and add a 100k-channel / 1k-group test of `group_of` and `ChannelList::build`.
5. **Split `iptv-app`:**
   - Move mpv and its platform glue into an `iptv-player-mpv` crate, behind a typed player-props contract shared with the Kotlin host.
   - Move import orchestration and the store worker into a native `iptv-runtime` crate, with one runtime and awaited channels.
   - Move the thread-local globals into explicitly owned state.
   - Add core-owned ID newtypes so the pure view-state modules can move into `iptv-core`.
6. **Add a second read-only WAL connection** for UI reads. Move `last_channel`, search history and settings writes off the UI thread, make them atomic, and keep them in the encrypted store.
7. **Testing:**
   - Fix the `personalization_appearance` race and replace fixed sleeps with event waits.
   - Add `cargo llvm-cov` to CI.
   - Split the fuzz target per parser, add HLS and DASH targets, keep a corpus, and run about 60 s on parser PRs.
   - Run the full `check.sh` crate set on Windows.
   - Add an Android emulator smoke test.
8. **Make NSH pinning verifiable.** Keep one `nsh.rev` file read by CI, `check.sh` and the README instructions. Fold the Windows patch into `tv-keys`, and work towards upstreaming.
9. **Platform trust and provenance:**
   - Configure macOS notarization secrets and sign the Windows installer.
   - Add `actions/attest-build-provenance`, signed `SHA256SUMS` and a CycloneDX SBOM.
   - Make Android release builds fail when there is no keystore, rather than falling back to the debug key.
   - Move `profileable` to a separate profiling build variant.
10. **Docs and process:**
    - Write a 2–3 page `docs/architecture.md`.
    - Add CONTRIBUTING, CHANGELOG and SECURITY.md.
    - Rewrite the comments that point at external reference docs so they describe the behaviour directly.
    - Lint for user-facing literals that bypass `tr()`.
    - Get at least one human reviewer on core and app PRs.
