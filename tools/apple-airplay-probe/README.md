# Apple AirPlay video probe

This developer build uses Patina's pinned NSH host to mount Apple's system route picker and an AVPlayer. It has its own bundle ID, `com.hantekllc.patina.airplayprobe`. The player accepts the two HLS channels generated by the fixture tool. The normal app exposes the same native adapter through the play bar’s destination picker, with its runtime-authorized opaque relay. This standalone probe uses fixture URLs directly and does not validate the product handoff or normal profile.

## Build and launch

Use an Apple silicon Mac with Xcode and the pinned NSH CLI from the [development setup](../../CONTRIBUTING.md). Set `NSH` to the CLI's absolute path if it lives outside the sibling checkout. From the repository root, choose the target for the sender.

```sh
tools/apple-airplay-probe/package.sh macos
open "target/airplay-probe/macos/Patina AirPlay Probe.app"
```

For a booted iPad simulator, check that the picker mounts and the status updates. The receiver and lock-screen checks require physical hardware.

```sh
tools/apple-airplay-probe/package.sh ios-simulator
xcrun simctl install booted "target/airplay-probe/ios-simulator/Patina AirPlay Probe.app"
xcrun simctl launch booted com.hantekllc.patina.airplayprobe
```

For a physical iPad, build with `tools/apple-airplay-probe/package.sh ios`. Sign the resulting app with a development identity and a provisioning profile that covers the probe's bundle ID before installing it on the registered device.

## Exercise a receiver

1. On a reachable LAN fixture server, run `bash tools/make-hls-fixtures.sh`, then `python3 tools/mock-server.py --loop 8089`. The server continuously serves the generated test pattern and color bars.
2. On the sender, enter the server's private IPv4 address and port, then select **Channel A**. Both sender and receiver must be able to reach the server.
3. Use the system picker to select an available video receiver. Press **Play**. On macOS the player can need an item before a video route becomes available. If needed, press **Play** before opening the picker. Check for moving video and sound at the receiver and `external playback on` on the sender. If the route stays selected and the status stays at `waiting`, record that the route has yet to start video playback. The probe continues waiting for external playback. If a load fails before granting Local Network access, grant access and press **Play** again to retry the selected channel.
4. Select **Channel B**, confirm the image and tone change at the receiver, then exercise **Pause**, **Play** and **Stop**. Start again and disconnect the receiver during playback. Check that the sender shows the route loss and stays silent.
5. For an iPad sender, background it and lock the screen during playback. Record whether the receiver continues playing, the audio stays at the receiver, and controls work after returning to the probe. For a Mac sender, test a separate video-capable receiver.

Record sender and receiver OS versions, each observed result, and the first failed step. A compile or simulator run covers only the sender software. The normal Patina library and player remain outside this probe.
